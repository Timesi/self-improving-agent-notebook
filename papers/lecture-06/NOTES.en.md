# Lecture 06 — Train-time scaling and reinforcement learning (study notes)

> This file is the paper study notes for CS329A lecture 6 (Train Time Scaling / Scaling RL), and the source material for the matching notebook.

> Papers: STaR (2203.14465), DeepSeekMath (2402.03300, including GRPO), DAPO (2503.14476)

## Lecture theme

The first five lectures (L1–L5) are all about **test-time compute**: the model is trained, weights frozen, and we spend more compute at inference — repeated sampling (L2 Large Language Monkeys), self-consistency voting, best-of-n reranking, verifier scoring (L3), code-execution feedback (L4), tree search (L5). Those methods assume "the model already reasons a little": we can only sample things that exist in the model's distribution.

Lecture 6 switches axis: **train-time scaling** — rather than spend more compute at inference, spend more compute at training so the model itself "becomes better at reasoning". The core tool is **reinforcement learning (RL)**: give the model a reward signal (whether the answer is correct) and let it explore better reasoning during training. This lecture's place is important: it opens Part 2 (Training & Evolution) and answers "where an agent's intelligence comes from". L7's open-ended evolution (an agent designs agents), L8's search augmentation, and later L9's post-training evolution all rest on this "train-time RL" foundation.

The three papers form a nested line:
1. **STaR** (2022): the smallest bootstrap loop. No reward model, no value network; "whether the answer is correct" is the filter signal; the model trains itself on its own correct reasoning. The idea's starting point.
2. **DeepSeekMath + GRPO** (2024): scale RL. Propose GRPO, drop PPO's value network, compute advantage from "group-relative" reward. Idea becomes method.
3. **DAPO** (2025): the last engineering step. The paper formula runs, but stable training at thousand-GPU scale still needs four engineering tricks. Method becomes system.

## Close reading

### Paper 1: STaR — Self-Taught Reasoner (arxiv:2203.14465, star.pdf)
- **Core idea**: bootstrap reasoning with reasoning. First let the model "explicitly generate intermediate reasoning steps (rationale) then the answer" (i.e. CoT), filter the samples that got the answer right, finetune on them, then generate again with the finetuned model, filter again, finetune again, and so on; the model gradually solves harder problems. Throughout, no human-written rationale, no separate reward model or value function, only "problem + gold answer" already in the dataset. The authors claim this is the first method that lets a pretrained LLM self-improve using its own language-modeling ability.
- **Key formulas / algorithms** (Algorithm 1):
  1. `M_0 ← M` (keep the original pretrained model; each round finetunes from it again, to avoid overfitting);
  2. Each round `n`: with `M_{n-1}`, few-shot generate rationale and answer `(r̂_i, ŷ_i)` for each problem;
  3. **Rationalization**: for problems whose generated answer is wrong, put the correct answer as a hint into the prompt, let the model "reason backwards" to generate rationale `(r̂^rat_i, ŷ^rat_i)`;
  4. Filter: `D_n = {(x_i, r̂_i, y_i) | ŷ_i = y_i}` (correct on generation), `D^rat_n = {(x_i, r̂^rat_i, y_i) | ŷ_i ≠ y_i and ŷ^rat_i = y_i}` (correct only with the hint); at training **do not put the hint in the prompt**, pretending the model thought of it itself;
  5. `M_n ← train(M, D_n ∪ D^rat_n)`.
  Only P=10 few-shot examples with rationales, plus a large dataset without rationales.
  The authors interpret STaR as an **approximation of policy gradient**: view M as a discrete latent-variable model `p_M(y|x) = Σ_r p(r|x)p(y|x,r)`, indicator reward `1(ŷ=y)`, expected reward `J = Σ_i E[1(ŷ_i=y_i)]`, whose gradient is
  `∇J = Σ_i E_{r̂,ŷ~p_M}[ 1(ŷ_i=y_i) · ∇ log p_M(ŷ_i, r̂_i | x_i) ]` (log-derivative trick). Filtering out rationales of wrong answers is equivalent to dropping the gradient of samples whose indicator is zero. STaR's two engineering approximations: (a) greedy decoding to lower variance (sacrificing exploration), (b) multiple gradient steps on the same batch.
- **Key experimental results** (base GPT-J 6B):
  - **Arithmetic**: after 16 outer-loop rounds, overall accuracy 89.5%; control (10k no-rationale examples finetuned 5000 steps) only 76.3%. Few-shot baseline is extremely low (2-digit addition <1%). With rationalization, 1 round of finetuning jumps 2-digit addition from <1% to 32%.
  - **CommonsenseQA dev**: Few-shot Direct 20.9% → Few-shot CoT 36.6% → Direct Finetune 60.0% → STaR without rationalization 68.8% (using only 69.7% of training data) → STaR + rationalization 72.5% (86.7% of data). Contrast: 30× larger GPT-3 Direct Finetune is 73.0% — **STaR with a 6B model matches a 30× larger model**.
  - **GSM8K test**: Few-shot CoT 3.1% → Direct Finetune 5.8% → STaR without rationalization 10.1% (only 25.0% of data) → with rationalization 10.7%.
  - Human evaluation: reviewers are 30% more likely to rank a STaR-generated rationale above a few-shot rationale (p=.039); 74% prefer STaR rationales over human-written ones (p<.001).
  - Ablation: keeping the few-shot prompt at finetune time helps (60.9→68.8 / 69.9→72.5); **raising sampling temperature cannot replace rationalization** (0.5/0.7 temperature is actually worse, tending to yield "right answer, wrong reasoning" samples).
- **Relation to the lecture theme**: STaR is the smallest prototype of "train-time scaling". It first shows that "the model's own correct reasoning can become its own training data", moving test-time "sample-filter" into the training loop. No reward model, no value function — planting the seed for later GRPO "dropping the critic"; its `p(r|x,y)` reverse inference (rationalization) is also a prototype of process supervision.
- **Demo-ready code points**: on any small dataset, implement STaR's outer-loop control flow (generate → filter → reverse-infer → merge dataset → finetune); with numpy verify Eq.2 policy-gradient equivalence (expected gradient under the log-derivative trick).

### Paper 2: DeepSeekMath (arxiv:2402.03300, deepseek-math.pdf, including GRPO)
- **Core idea**: two hands — (1) build high-quality math corpus 120B tokens (iterative fastText classifier + human labels from Common Crawl, 9× OpenWebMath), continue-pretrain DeepSeek-Coder-Base-v1.5 7B into DeepSeekMath-Base; (2) propose **Group Relative Policy Optimization (GRPO)**, further lift reasoning with RL after instruction finetuning. GRPO is a PPO variant: **drop the critic (value network)**, use "the mean reward of a group of sampled outputs for the same problem" as baseline, substantially lowering memory and compute.
- **Key formulas / algorithms**:
  - **PPO reference** (Eq.1): `J_PPO(θ) = E_{q,o}[ 1/|o| Σ_t min( r_t(θ) A_t, clip(r_t(θ), 1-ε, 1+ε) A_t ) ]`, where `r_t(θ) = π_θ(o_t|q,o_<t)/π_θold(o_t|q,o_<t)`, advantage `A_t` from GAE using a **learned value function** `V_ψ`; the KL penalty is added into the per-step reward: `r_t = r_φ(q,o_≤t) − β log(π_θ/π_ref)`. Problem: the value network is as large as the policy, doubling memory; and reward is given only on the last token, so per-token values are hard to train accurately.
  - **GRPO objective** (Eq.3):
    `J_GRPO(θ) = E_{q, {o_i}_{i=1}^G}[ 1/G Σ_i 1/|o_i| Σ_t { min( r_{i,t}(θ) Â_{i,t}, clip(r_{i,t}(θ), 1-ε, 1+ε) Â_{i,t} ) − β D_KL(π_θ ‖ π_ref) } ]`.
    Sample **G outputs** per problem as a group; advantage is fully determined by **group-relative reward**.
  - **Outcome supervision**: `Â_{i,t} = r̃_i = (r_i − mean(r)) / std(r)`, assign that output's normalized reward to every token in the output.
  - **Process supervision**: first normalize each step (identified by ending token index(j)) `r̃_{index(j)}`, then `Â_{i,t} = Σ_{index(j)≥t} r̃_{index(j)}` (sum of normalized rewards of all steps after this token).
  - Two key differences from PPO: (a) KL is moved from the reward into the loss as `−β D_KL(π_θ ‖ π_ref)`, with unbiased estimate `D_KL = π_ref/π_θ − log(π_ref/π_θ) − 1` (non-negative, Schulman 2020); (b) advantage uses in-group statistics, no value network.
  - Algorithm 1 (Iterative GRPO): each round set reference to the current policy, sample a batch → update old policy → sample G outputs per problem → compute rewards → compute `Â` → do μ GRPO updates; the reward model is continuously updated with replay (including 10% historical data).
  - Hyperparameters: policy LR 1e-6, KL coefficient β=0.04, 64 outputs per problem, max length 1024, batch 1024.
  - **Unified paradigm** (Eq.5): `∇J_A(θ) = E_{(q,o)~D}[ 1/|o| Σ_t GC_A(q,o,t,π_rf) ∇ log π_θ(o_t|q,o_<t) ]`. All methods (SFT/RFT/DPO/Online RFT/PPO/GRPO) split into a three-piece set: data source D, reward function, gradient coefficient GC. The only difference between GRPO and Online RFT is that GC varies with reward magnitude — wrong problems are not only unrewarded but punished by magnitude.
- **Key experimental results**:
  - DeepSeekMath-Base 7B: GSM8K 64.2%, MATH 36.2%, **above Minerva 540B** (parameter count is not the only factor; data quality matters).
  - GRPO does RL only on the SFT subset of GSM8K/MATH (about 144K problems), yielding DeepSeekMath-RL 7B: GSM8K 82.9%→**88.2%**, MATH 46.8%→**51.7%** (first open-source non-tool MATH above 50); **out of domain** CMATH 84.6%→88.8% also rises. MATH with 64-way self-consistency reaches **60.9%**.
  - Ablation (figure 5, 1.3B): Online RFT > RFT (online sampling beats offline); **GRPO > Online RFT** (modulating the gradient coefficient by reward magnitude is more efficient); **GRPO+PS > GRPO+OS** (process supervision is finer). Iterative RL lifts substantially, most in the first round.
  - Pretraining lesson: code training lifts math reasoning (two-stage code 400B → math 150B is best); arXiv paper corpus is almost useless for math reasoning.
- **Relation to the lecture theme**: GRPO is the lecture's **technical core** — turning "RL improves reasoning" into a reproducible, memory-controllable formula. It shows evolution from STaR's "indicator reward" to "continuous reward + in-group normalized advantage", the direct starting point of later DAPO. The unified paradigm (data source / reward / gradient coefficient) gives readers a thinking tool to put various training methods in one frame.
- **Demo-ready code points**: implement GRPO advantage and loss from scratch in numpy/torch; contrast PPO (value network + GAE) and GRPO (in-group normalization) objectives in code; demonstrate outcome vs process supervision advantage propagation; write SFT/RFT/GRPO as the same `gradient_coefficient` function under the unified paradigm.

### Paper 3: DAPO — Decoupled Clip and Dynamic sAmpling Policy Optimization (arxiv:2503.14476, dapo.pdf)
- **Core idea**: OpenAI o1 and DeepSeek R1 technical reports hide RL training details, so community reproduction is hard. The authors with naive GRPO on Qwen2.5-32B only reach AIME 30 (DeepSeek 47), so they fill in the missing engineering between "paper formula" and "stable training at thousand-GPU scale", propose DAPO, and **fully open-source** it (code on the verl framework + data DAPO-Math-17K), reaching 50 on AIME 2024 with Qwen2.5-32B. The core is four tricks: **Clip-Higher, Dynamic Sampling, Token-Level Policy Gradient Loss, Overlong Reward Shaping**. DAPO also **drops the KL penalty** (a long-CoT model's distribution already differs a lot from the reference; KL constraint is unnecessary).
- **Key formulas / algorithms**:
  - **Rule reward** (Eq.7): `R(ŷ,y) = 1 if is_equivalent(ŷ,y) else −1`. Verifiable tasks grade answer correctness directly, no learned reward model, avoiding reward hacking. The dataset unifies answers as integers for easier parsing.
  - **DAPO objective** (Eq.8/12):
    `J_DAPO(θ) = E[ 1/Σ_i|o_i| Σ_i Σ_t min( r_{i,t}(θ)Â_{i,t}, clip(r_{i,t}(θ), 1−ε_low, 1+ε_high)Â_{i,t} ) ]`, constraint `0 < #{o_i correct} < G`;
    advantage is still `Â_{i,t} = (R_i − mean({R_i}))/std({R_i})`.
    Difference from GRPO: the normalizer changes from `1/G Σ_i 1/|o_i|` (sample-level) to `1/Σ_i|o_i|` (**token-level**); clip thresholds decouple into `ε_low`, `ε_high`.
  - **Clip-Higher**: default ε=0.2, the upper bound limits probability lifts of "exploratory tokens" — a low-probability token (e.g. π=0.01) has upper bound only 0.012, hard to rise; a high-probability token (0.9) has upper bound 1.08, already unconstrained. This leads to entropy collapse, in-group outputs becoming similar. Fix: `ε_low=0.2, ε_high=0.28`, raise the upper bound so low-probability tokens have room to rise, keeping exploration. Leave the lower bound (raising it further easily pushes probability to 0 and collapses the sampling space).
  - **Dynamic Sampling**: if a prompt's G outputs are **all correct or all wrong**, in-group advantage is 0 → gradient is 0, effective batch size falls over time, gradient variance grows. Fix: **oversample and filter prompts whose correctness rate is 1 or 0**, keep only samples with `0<correct count<G`, guaranteeing every batch has a usable gradient.
  - **Token-Level Loss**: GRPO's sample-level loss equal-weights each sample, so a single token's gradient contribution in a long answer is diluted; nonsense/repetition in long samples is not punished → entropy and length grow unhealthily. After switching to token-level (`1/Σ|o_i|`), the same pattern is promoted/suppressed equally whether it appears in a short or long answer.
  - **Overlong Reward Shaping**: the default punitive reward on truncated samples introduces noise (the reasoning is correct, it is just too long). First **Overlong Filtering** (mask truncated samples' loss) to stabilize training, then **Soft Overlong Punishment**:
    `R_length(y) = 0` (`|y| ≤ L_max−L_cache`); `(L_max−L_cache−|y|)/L_cache` (`L_max−L_cache < |y| ≤ L_max`); `−1` (`|y| > L_max`).
    Hyperparameters: max length 16384 + cache 4096 = 20480.
- **Key experimental results** (AIME 2024, avg@32):
  - DAPO + Qwen2.5-32B = **50**, above DeepSeek-R1-Zero-Qwen-32B (47), and **using only 50% of its training steps**.
  - Piecewise stacking: Naive GRPO **30** → +Overlong Filtering **36** → +Clip-Higher **38** → +Soft Overlong Punishment **41** → +Token-level Loss **42** → +Dynamic Sampling (DAPO) **50**. Each trick contributes several points.
  - Training-dynamics monitoring trio: generation length (a proxy for exploration space, may stall/fall), reward curve (train-set reward correlates weakly with validation accuracy, watch overfitting), generation entropy (too low = lost exploration, too high = nonsense).
  - Hyperparameters: AdamW, LR 1e-6, prompt batch 512, 16 responses per problem, mini-batch 512, 16 gradient updates/rollout, eval temperature 1.0 / top-p 0.7.
- **Relation to the lecture theme**: DAPO answers "the formula running ≠ the system running". It upgrades GRPO from a paper to an industrial RL system; the four tricks are all engineering tradeoffs for stable training (exploration vs exploitation, sample efficiency, token weights, truncation noise). For an agent course: real agent post-training (L9) is a system of DAPO's scale; this lecture gives monitoring metrics and a failure-mode list.
- **Demo-ready code points**: numerical demo of entropy collapse (how ε upper/lower bounds differ in how much low/high-probability tokens can rise); simulate a zero-gradient group and show effective gradient before/after dynamic sampling; numpy hand-calculate the piecewise soft overlong punishment; contrast sample-level vs token-level loss weights on short vs long samples.

## Teaching thread (how a Stanford instructor might teach this)

1. **Pick up the previous lecture, flip the axis**: first recap test-time compute — "a problem the model cannot do will not be done by sampling ten thousand times; that is only luck". So rather than spend more compute at inference, let the model actually learn to reason at training. Use L2's self-consistency curve: the same money spent on training lifts the model's own ability.
2. **STaR builds the smallest bootstrap loop**: problem — constructing a rationale dataset is expensive (human labels) or needs existing solution templates. STaR's answer: do not construct; let the model generate, **use whether the answer is correct as a filter**. Draw the loop (Fig.1): generate → filter the correct ones → finetune → generate again. Key intuition: correctness is a binary reward; STaR is a policy gradient with "reward = indicator, no critic" (Eq.2). Where readers stall: "the model only generates problems it can do, so hard problems are never learned" — that is exactly why rationalization exists: put the correct answer as a hint, let the model "reason backwards", and at training pretend there was no hint. Use arithmetic experiment curves (1-digit first, then 2-digit, …) to show staged lifts and how rationalization learns several lengths at once.
3. **DeepSeekMath scales RL**: STaR's reward is binary (right/wrong); now switch to a continuous reward model + explicit RL. First give the PPO formula (Eq.1): train policy + value network, two large models, memory doubles, per-token values are hard to train. **GRPO's key move**: replace the value network with "the mean of G samples of the same problem", advantage becomes in-group z-score (Eq.3). Hand-push once: `r̃_i = (r_i − mean(r))/std(r)`, all-correct group advantage=0 (planting a mine for DAPO), only a half-right half-wrong group has positive/negative split. Then outcome vs process supervision advantage propagation. String SFT/RFT/DPO/GRPO with the unified paradigm (data source / reward / gradient coefficient) — readers will see they are just different combinations of the same three-piece frame.
4. **DAPO fills in engineering details**: the instructor stresses "did the paper reproduce?" — naive GRPO is only 30. Cover the four tricks one by one, each with an intuitive failure case: entropy collapse (Clip-Higher), all-correct group zero gradient (Dynamic Sampling), long-sample nonsense (Token-Level Loss), truncation mis-penalty (Overlong Reward Shaping). Use the AIME stacking curve (30→50) so readers see how many points each trick is worth. Finally monitoring: length, reward, entropy trio.
5. **Close on agents**: these three papers together are the full recipe of "train-time scaling" — STaR's idea (bootstrap), GRPO's algorithm (group-relative), DAPO's engineering (stable at scale). Preview L7: once a model can self-improve, we can let an agent design agents; L9 post-training evolution will reuse this RL recipe. Readers easily confuse "train-time scaling" with L2 "test-time scaling"; the instructor distinguishes in one sentence: test-time scaling changes the **sampling distribution**, train-time scaling changes the **model parameters**.

1. **Numpy hand-calculate GRPO advantage and loss**: a small problem, G=4 outputs and rewards (e.g. `r = [1, -1, 0, 1]`, correct/wrong/partial), hand-calculate in-group mean, std, normalized advantage `(r−mean)/std`; then a toy importance-ratio list `r_ratio = π_θ/π_θold`, implement `min(ratio·Â, clip(ratio,1−ε,1+ε)·Â)`, print each token's contribution. Expected output: all-correct group advantage all 0, gradient 0 (leads to DAPO's motivation).
2. **GRPO vs PPO formula visualization**: implement both objectives in numpy, x-axis importance ratio, y-axis objective value, show how clip freezes the objective when `r` leaves `[1−ε,1+ε]`; list a component table: PPO needs a value network + GAE, GRPO only in-group statistics. Expected output: the objective "plateau" curve from clip, seeing the trust-region constraint.
3. **Mini STaR loop (control flow + data construction)**: do not train a large model; with a small toy dataset (e.g. 100 integer-addition / multiple-choice problems) simulate STaR's three steps: `generate → filter(D_n) → rationalize(D^rat_n)`, using llm_client (scripted mode, deterministic output) or a rule fake model to give (rationale, answer), filter by `ŷ==y`. Focus: how the outer-loop dataset inflates round by round, how rationalization supplies "generation failed but reverse-inference succeeded" samples, and the plateau of "all correct then stall". Expected output: dataset-size growth curve + accuracy lift.
4. **Unified paradigm: one table of gradient coefficients**: implement SFT/RFT/Online RFT/GRPO gradient coefficients `GC(q,o,t,π_rf)` each as a function, print GC of each method on the same batch of (question, output), observe that RFT only rewards never punishes, GRPO rewards/punishes by magnitude. Expected output: a DataFrame, seeing "why GRPO is more efficient than Online RFT".
5. **Numerical demo of entropy collapse and Clip-Higher**: given `π_θold = 0.01` (exploration token) and `0.9` (exploitation token), compute liftable upper bounds under ε=0.2 vs ε=0.28, plot "low-probability tokens crushed by the upper bound, high-probability tokens already unconstrained", reproducing the entropy-drop intuition of paper Fig.2b. Expected output: clip-upper-bound curves, understanding "why raising ε_high keeps exploration".
6. **Token-level vs sample-level loss weights**: construct a short sample (|o|=10) and a long sample (|o|=100), hand-calculate each token's actual weight under the two normalizers (`1/G Σ 1/|o_i|` vs `1/Σ|o_i|`), showing that a single token in a long sample is diluted under sample-level loss. Expected output: per-token weight comparison numbers.
